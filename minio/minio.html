What MinIO Is

MinIO is a high-performance object storage server that exposes an S3-compatible API. It gives you a local or self-hosted way to work with buckets, objects, and common S3 operations without depending on AWS infrastructure during development.

That makes it useful for testing applications that upload files, download files, store generated documents, or manage media assets. If your application already speaks S3, MinIO lets you run the same pattern locally with very little code change.

The AWS SDK can talk to MinIO by pointing the client at the MinIO endpoint, enabling path-style requests, and using the MinIO access key and secret key as credentials.

Using AWS SDK Locally

With MinIO running locally or inside k3s, the AWS SDK for .NET can read and write S3-compatible buckets the same way it would against Amazon S3. Typical operations include creating a bucket, uploading an object, downloading an object, and listing available buckets.

In practice, local development usually looks like this:

  1. Start MinIO and expose the S3 API on port 9000.
  2. Configure the SDK to use the MinIO endpoint instead of AWS.
  3. Use MinIO credentials from your Kubernetes secret or local environment variables.
  4. Run your application code unchanged apart from endpoint configuration.

1. Prerequisites

  • A running k3s cluster
  • Kubectl configured for the cluster
  • Helm installed
  • Longhorn StorageClass available
  • Node named turing-four if using current nodeSelector

2. Add MinIO Helm Repo

helm repo add minio https://charts.min.io/
helm repo update

3. Create Namespace, Secret, and PVC

kubectl create namespace minio --dry-run=client -o yaml | kubectl apply -f -
kubectl apply -f secret.yaml
kubectl apply -f pvc.yaml

4. Install MinIO

chmod +x install.sh
./install.sh

The script runs Helm upgrade/install with values from values.yaml.

5. Verify and Access Console

kubectl -n minio get pods
kubectl -n minio get svc
kubectl -n minio get pvc s3-pvc
kubectl -n minio get svc minio-console

If your cluster does not provide external LoadBalancer IPs, use:

kubectl -n minio port-forward svc/minio-console 9001:9001

Then open http://localhost:9001.

Default credentials from secret.yaml are weak and should be changed before non-local use.

AWS SDK for .NET (C#) with MinIO

MinIO is S3-compatible, so the AWS SDK for .NET works with a custom service URL and path-style addressing.

Install SDK

dotnet new console -n MinioS3Demo
cd MinioS3Demo
dotnet add package AWSSDK.S3

Example: create bucket, write object, read object

using Amazon;
using Amazon.Runtime;
using Amazon.S3;
using Amazon.S3.Model;
using Amazon.S3.Util;

var endpoint = "http://127.0.0.1:9000";
var accessKey = Environment.GetEnvironmentVariable("MINIO_ROOT_USER") ?? "admin";
var secretKey = Environment.GetEnvironmentVariable("MINIO_ROOT_PASSWORD") ?? "password";

var config = new AmazonS3Config
{
    ServiceURL = endpoint,
    ForcePathStyle = true,
    AuthenticationRegion = "us-east-1"
};

using var s3 = new AmazonS3Client(
    new BasicAWSCredentials(accessKey, secretKey),
    config
);

var bucketName = "demo-bucket";
var objectKey = "hello.txt";

if (!await AmazonS3Util.DoesS3BucketExistV2Async(s3, bucketName))
{
    await s3.PutBucketAsync(new PutBucketRequest
    {
        BucketName = bucketName
    });
}

await s3.PutObjectAsync(new PutObjectRequest
{
    BucketName = bucketName,
    Key = objectKey,
    ContentBody = "Hello from MinIO via AWS SDK for .NET"
});

var objectResponse = await s3.GetObjectAsync(new GetObjectRequest
{
    BucketName = bucketName,
    Key = objectKey
});

using var reader = new StreamReader(objectResponse.ResponseStream);
var content = await reader.ReadToEndAsync();
Console.WriteLine($"Read object: {content}");

var buckets = await s3.ListBucketsAsync();
Console.WriteLine("Buckets:");
foreach (var bucket in buckets.Buckets)
{
    Console.WriteLine($"- {bucket.BucketName}");
}
If MinIO runs inside k3s without external access, port-forward the S3 API service on port 9000 to localhost first, then use that URL in the C# client.
